# mindie-agent-wb 0.1.14: Storage Lifecycle Governance and External Cache Unpinning

[中文](mindie-agent-wb-0.1.14.md)

- **Cross-process update mutex and WorkBuddy external cache unpinning (`component_update.py`, `wb_install.py`, `storage_lifecycle.py`)**: Component updates take a cross-process lock at `<data_home>/wb-component-update.lock`; a contender returns `status="busy"` instead of overwriting state or building again. Install and upgrade flows scan only existing MindIE WorkBuddy plugin caches, atomically rebind pinned Python interpreters in `hooks.json`, `mcp.json`, and `.mcp.json`, and retain the active version plus one rollback generation. Superseded cache generations leave through a two-phase rename without touching unregistered account state. Rollback ranking accepts formal versions only: leftover `.trash-*` remnants are swept first and non-semver names never occupy the rollback slot. Any cache manifest reached through a symlink or Windows junction into an external Git checkout or a configured source root is reported and left intact.
- **Silent reclamation of historical baggage**: After a successful switch, bounded `mindie_knowledge.storage.prune_component_runtimes` and `sweep_legacy_installations` calls reclaim incomplete failed `.venv` generations without `components.json`, excess `wb-state/component-runtimes/*`, old `wb-source/*`, and leftover `.trash-*`. Cross-plugin borrowed sibling-host interpreters, an external Git checkout referenced by `wb.json["source_root"]`, live lease-holding children, and Git metadata are always preserved. Even when a caller narrows `--config`, the sweep also reads the default config homes (`MINDIE_CONFIG_HOME`, `~/.config/mindie-agent`) and holds a shared lease on every interpreter generation borrowed by their `codex.json`/`cc.json` for the whole reclamation. Local occupancy or budget expiry is reported as `cleanup_warning` only; the primary result remains `status="updated"` and a confirmed primary receipt is never relabelled `receipt_unconfirmed=True`.
- **Update failure classification (`component_update.py`, `diagnostic_support.py`)**: Updater faults are classified from typed facts, never exception text. A DNS failure (`resolver`), `busy`/`deferred`/`prerequisite`, a lock timeout, `ENOSPC`, or `PermissionError` is always `reportable=False` and is never misreported as an interior product bug; genuine artifact faults are still reported.
- **Resident MCP runtime lease and cold-start cache placement (`mcp_server.py`, `setup.py`)**: The resident MCP facade and its single-request children hold a shared `acquire_runtime_lease(...)` for `owning_dir(sys.executable)`, so reclamation cannot retire a generation that is still serving. A first `wb-venv` bootstrap that has no explicit `UV_CACHE_DIR` and crosses volumes now uses the same-volume `<data_home>/.uv-cache`.
- **Test isolation and temporary-directory governance (`tests/conftest.py`, `tests/test_runtime_upgrade.py`, `tests/test_storage_lifecycle_wb.py`)**: Tests now fully isolate `HOME`, `USERPROFILE`, `MINDIE_*`, `TMPDIR`, and `UV_CACHE_DIR`; Windows `mwb-*` directories are removed in `finally` with retries; the old-runtime acceptance run uses pytest's isolated `tmp_path` and no longer writes multi-generation virtualenvs next to the checkout. `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `KIMI_SHARE_DIR`, `DSH_HOME`, `OPENCODE_CONFIG_DIR`, and `WORKBUDDY_HOME` are now isolated so tests never read the real `~`. Cross-platform storage lifecycle regressions cover failed `.venv` trees, multiple runtime/source generations, old plugin caches, interpreter rebinding, borrowed interpreters, and live-lease protection, plus three new cases: a runtime borrowed by the default config home survives both reclamation phases under a narrowed `--config`, sweeping `.trash-*` keeps the formal rollback version, and a `hooks/` link to an external Git checkout leaves its `hooks.json` byte-for-byte unchanged. `mcp_server.py` stays under 800 lines.
